# Worms v3 — Clean TypeScript 2D Rewrite Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the math-generated worm ecosystem as strict, testable TypeScript with a simulation core fully decoupled from rendering, so a 3D renderer can later be added without touching the math.

**Architecture:** Three layers — `core` (pure math: vectors, RNG, angles), `simulation` (headless world: worms, harmonics, food, eggs, lifecycle; zero DOM/canvas imports), `render` (a `Renderer` interface with a Canvas2D implementation first). Fixed-timestep loop drives simulation; renderer consumes read-only state.

**Tech Stack:** Vite 7, TypeScript 5 (`strict` + `noUncheckedIndexedAccess`), ESLint (typescript-eslint strict, `no-explicit-any: error`), Prettier, Vitest for the simulation core. No runtime dependencies for the 2D phase.

## Part 0: What `_old` actually contains (archaeology)

The `_old` tree is a ~2016 Backbone/jQuery SPA (webpack 1, gulp). Almost all of it is boilerplate irrelevant to the project: `extends/` (Backbone modules, jForm, jQuery plugins, locale/layout managers), `router.js`, `layouts/`. **The essence lives in `_old/src/modules/index/v/worms/` (5 small files):**

### The shape math (`worm.js` → `fY`, the heart of the project)

A worm is a spine of N segments; segment `i` has a half-width given by the sum of three harmonics (comments in the original name them affectionately):

```
w(i, t) = |sin(π · i / L)| · W                          — body envelope (harmonic 1)
        + (i + L/10)^(1.4 − i/L)                        — head thickening (harmonic 2)
        + |sin((t − 10i) / 200)| · (v + i/10)           — traveling body wobble (harmonic 3)
```

where `L` = length in segments, `W` = base width, `v` = current velocity, `t` = time (ms). Each segment takes the **max of w over 2 consecutive samples**. The worm is drawn as a series of strokes perpendicular to the spine (length `2·w(i)`), giving the signature bristly look.

### Spine kinematics (`wormLine.js`)

Follow-the-leader IK: segment `i` trails segment `i−1` at rest distance `5`, clamped to `[5·0.6, 5·1.4]`, with `angle = atan2` toward the previous segment. When dying, every rendered point gets multiplicative jitter `(1 − rand·0.01)`.

### Behavior (`worm.js` → `live`)

- Picks a random meatball as target; velocity = `min(maxV, dist·0.04) · (1 + sin(t/100))` — the sin term produces peristaltic surging.
- Steering with max turn rate `4π/360` rad/frame, with proper ±π wraparound.
- Slows to 50%-scaled velocity within 100 px of world edges; slows 0.4× within 50 px of target; eats within 10 px.
- Eating grows the worm by meatball type: LENGTH `+value/2`, WIDTH `+value/3`, POWER (max velocity) `+value/32`.
- Opacity pulses: `0.8 + |sin(t/300)|·0.2`.
- Dies when `length > MAX_LENGTH` (randomized `37..~148`): 3 s fade with velocity decay + jitter, then spawns an egg.

### Ecosystem (`world.js`, `egg.js`, `meatball.js`, `helpers.js`)

- World: 2 worms, 20 meatballs, 2 eggs at start; eaten meatballs respawn; click toggles pause.
- Egg: concentric wobbly polygons (6–9 random angular dots, 5–8 rings pulsing via `1 − sin((t − k·300)/300)·0.9`), radius grows ×1.0038/frame, hatches after randomized 3–9 s (×1.4/frame growth burst for 200 ms) into a new worm.
- Meatball: pulsing concentric rings (`r = value·(1 + sin(t/250)·0.1)`), radial gradient black→type color; types LENGTH=green, WIDTH=blue, POWER=red, value 10–20. (Bug in original: `seed = 1 + floor(rand·3)` means TYPE_LENGTH/`case 0` is unreachable — worms only ever find width/power food plus the `default` fallthrough for seed 3.)
- Colors: random RGB channels each ~`30 + (220 − rand·220)`, i.e. muted pastels.

### The deleted v2 (git HEAD, now removed from worktree)

A Vite + TS + Three.js 3D attempt (instanced torus rings, FPS camera, GLSL shaders). Largely generated code, abandoned. Worth keeping only as ideas: instanced rendering for 3D, params-object constructors, pluggable color functions. The 2D rewrite does not build on it.

## Part 1: Design decisions (proposed — confirm before executing)

| # | Decision | Recommendation | Rationale |
|---|----------|----------------|-----------|
| 1 | 2D renderer tech | **Canvas2D** (raw, no lib) | The old look is stroke-based; Canvas2D reproduces it exactly, zero deps. WebGL only if profiling demands it. |
| 2 | Scope of v3 2D | **Full ecosystem** (worms + food + eggs + lifecycle) | It's what makes the piece alive; the sim layer makes it cheap to keep. |
| 3 | Harmonics API | **Composable list of named `Harmonic` functions** `(ctx: HarmonicContext) => number` summed by a `WidthProfile` | "Several harmonics describing their shape" is the stated core; making them first-class enables live tuning and per-worm variation. |
| 4 | 3D readiness | Sim emits a **`WormSnapshot` = spine points + radius profile + color**; renderers interpret it (2D: perpendicular strokes / ribbon; 3D later: tube loft) | The math never learns about rendering; 3D becomes "write a new Renderer". |
| 5 | Vectors | Concrete immutable-style `Vec2` now; sim code written against it, not a generic N-dim abstraction | YAGNI: a generic VecN complicates everything for a 3D that will need its own steering anyway. The snapshot boundary (decision 4) is the real 3D seam. |
| 6 | Determinism | **Seedable RNG** (mulberry32) injected everywhere; fixed timestep (`dt`-based, not frame-based) | Makes the sim unit-testable and reproducible; old code was frame-rate dependent. |
| 7 | Old quirks | Fix the unreachable-LENGTH-type bug; convert all `/frame` constants to `/second` | Preserve the aesthetic, not the bugs. |
| 8 | Debug tooling | Minimal custom overlay panel (FPS, entity counts, live harmonic sliders) — no lil-gui dependency | Live-tuning harmonics is the main elaboration workflow. |
| 9 | Self-intersection | **Width-derived turn limits at two levels**: steering caps head turn rate so turning radius ≥ local body radius; spine clamps per-joint bend angle to `spacing / minRadius(i)` | Prevents body overlap when turning without expensive segment-segment collision resolution; local, cheap, and translates to a cone constraint in 3D. |
| 10 | Obstacle avoidance | **Feeler-based steering over circle obstacles**: worm bodies = capsule chains (circle per segment, r = local half-width), eggs = circles; forward feeler finds nearest threat, lateral avoidance blended with seek | Classic Reynolds avoidance; ~300 circles total so brute-force queries suffice (spatial grid noted as future optimization). Own-body segments beyond a head-exclusion window participate too, discouraging wide self-crossings. |

## Part 3: Type discipline rules (applies to every task)

- `"strict": true`, `"noUncheckedIndexedAccess": true`, `"exactOptionalPropertyTypes": true`.
- ESLint: `@typescript-eslint/no-explicit-any: error`, `strict-type-checked` preset. `unknown` + narrowing typeguards at every boundary (input events, JSON, panel values).
- Entity kinds and food kinds are **discriminated unions** (`kind: "worm" | "egg" | "food"`, `foodKind: "length" | "width" | "power"`) — `switch` + `assertNever` for exhaustiveness, never enums-as-numbers like the old `TYPE_LENGTH = 1`.
- All time in **seconds**, all rates per-second; `dt` passed explicitly. No `Date.now()` inside simulation.
- No classes reaching into each other's fields (old code mutated `oWorld.oMeatballs` from inside Worm) — worms request actions via World methods / returned intents.
